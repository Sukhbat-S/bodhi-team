# Changelog

## 1.1.0-preview.3

- Windows through WSL2 (Ubuntu 24.04 or 22.04), and Linux generally. `scripts/bootstrap-personal-linux.sh` mirrors the macOS bootstrap's contract: same flags, dry run by default, the same refusals (existing database, `.env` or `AGENTS.md`), pinned manifest identity for `--apply`, loopback-only service. Its preflight also reports the WSL generation, the distribution and systemd state with the exact fix, and refuses WSL1, the `docker-desktop` distribution, a checkout under `/mnt`, and Windows `node`/`npm`/`git` on the Linux `PATH`. Prerequisites come from Ubuntu, PGDG (PostgreSQL 18, `postgresql-18-pgvector`) and NodeSource (Node 24, npm 11); the preflight prints the exact commands. Both apt signing keys are downloaded as the user and installed only when their full fingerprints match the pinned values.
- PostgreSQL on Linux does not use Homebrew-style local trust, because WSL2 forwards loopback ports to Windows. Setup runs through the local socket with peer authentication. `--apply` gives the owner's role a generated password, sends PostgreSQL only its SCRAM-SHA-256 verifier, and stores the password only in `DATABASE_URL` in `.env` (mode 0600); it is never printed, and a failed install clears it before dropping the database, so a retained database never blocks a re-run. The preflight refuses non-loopback `listen_addresses`, any `pg_hba.conf` host rule that could admit the role to the BODHI database without scram-sha-256 on loopback, a loopback TCP login without a password, and a role that already has a password. Upgrades carry `.env` over unchanged.
- Isolated dependency builds on Linux run in a bubblewrap sandbox (fresh namespaces, only the stage writable, home, `/tmp` and `/run` unmounted), the counterpart of macOS `sandbox-exec`, with the same isolation probe plus a loopback check. bubblewrap cannot filter ports the way the macOS profile does, so only `npm ci --ignore-scripts` gets the network; the native rebuild and the workspace build run offline, and better-sqlite3 compiles from its bundled source (about a minute). The macOS path is unchanged.
- `scripts/install-systemd-user-service.sh`: a per-user systemd unit (restart on failure, journald logs, linger), with ownership checks like the LaunchAgent's. `scripts/start.sh` installs it on Linux when a systemd user manager answers, and otherwise keeps its detached-process fallback; under systemd its log hints name `journalctl --user -u <unit>`. `service-ownership.ts` recognises, stops and refuses to replace a foreign unit on Linux only, and identifies Linux processes by `/proc/<pid>/exe`: `ps -o comm=` reports Node 24's main thread as `MainThread`, which made `stop.sh` and `start.sh` treat BODHI's own server as foreign. A ` (deleted)` suffix (Node upgraded under a running server) is ignored, and `dash` counts as a shell, as Ubuntu's `/bin/sh`.
- `scripts/upgrade-personal-linux.sh` and `scripts/activate-personal-voyage-linux.sh`: Linux counterparts of the macOS upgrade (manifest, backup, compatibility and rollback checks, systemd in place of launchd) and Voyage activation (key validated, stored only in `.env` at mode 0600, never echoed).
- `install-harness.mjs --platform macos|wsl|windows-host` (auto-detected when omitted). `windows-host` copies skills and agent cards into the Windows profile with an ownership marker (a `--force` backup goes outside the skill discovery root), and prints Codex `config.toml`/`hooks.json` and Claude Code `claude mcp add`/`settings.json` registrations that run the same MCP launcher and hooks inside WSL through `wsl.exe -d <distro> --exec`.
- `docs/windows-wsl2.md`: installation, service, both harness topologies, verification and troubleshooting (systemd, localhost forwarding, Windows-side harness, sleep and restart, CRLF line endings).
- Behaviour change on macOS: `upgrade-personal-macos.sh` now selects any Node 24 without loading native modules from the unpacked release (`resolve_bodhi_node --no-native-modules`). Before, run from a freshly extracted package, which has no `node_modules`, it stopped with "cannot find a Node 24 runtime" unless `BODHI_DIR` pointed at an installed checkout. Its helpers need no native module, and dependencies are still built inside the isolated stage. The Linux upgrader does the same.
- `install-harness.mjs --help` now lists `--platform` and notes that it is auto-detected.
- Release contract: the new scripts and guide are shared release files; manifests may declare `linux-x64` and `linux-arm64`, and new packs do.

Known limits: the WSL2 path has been exercised in Ubuntu 24.04 containers on arm64, not yet on a real Windows machine; WSL localhost forwarding, distribution idle shutdown and a Windows-side harness launching the MCP server through `wsl.exe` are documented but unverified.

## 1.1.0-preview.2

- Codex and Claude Code are peer harnesses over one substrate (ADR-004). New `templates/claude-code/` (global and project instruction templates, `bodhi-scout`/`bodhi-crit`/`bodhi-impl` agent cards, settings snippet, PreCompact and post-compaction recall hooks) and `templates/codex/` (global instructions, `config.toml`, `hooks.json` and plugin marketplace snippets).
- `scripts/install-harness.mjs` (`npm run harness:install`): dry run by default, `--apply` to link skills into `.agents/skills` and `.claude/skills` (optionally the user roots), copy agent cards and write a thin `CLAUDE.md`; prints all configuration to merge by hand. `npm run skills:install` now delegates to it, is idempotent, and prunes links to retired skills.
- New harness identity hook `scripts/harness-session-lifecycle.sh` (`codex` or `claude-code`): a SessionStart hook that injects the native task identity used by `$session-start` and `$session-save`. Wire it with `templates/codex/hooks.snippet.json` or `templates/claude-code/settings.snippet.json`. The policy packet accepts and echoes a validated `provider`, no longer filters trust-tier classes or memories by vendor name or model codename (only the `model-routing` and `quota` tags are excluded), and drops its project-specific main-push branch.
- Learning loop retired: skill-learning and workflow-candidate routes, services and the scheduler job are removed. The MCP server exposes 24 tools (was 30) and the scheduler retains 8 jobs (was 9). Codex plugin version bumped and bundle regenerated; reinstall the plugin. No schema changes or migrations; the retired tables remain untouched.
- LaunchAgent install kicks the job after bootstrap; the MCP start banner counts tools from the live registry.
- Skills: `session-start` and `session-save` are harness-neutral with Claude Code routing; descriptions rewritten as typed triggers; `interface-review`, `first-principles-decision`, `product-discovery`, and the MIT-licensed forks `emil-design-eng` and `better-ui` added; eight skills retired or merged (see README).
- `skill-evals/` wrapper for measuring skill firing with `claude plugin eval`, with one example case.
- `docs/dual-harness-orchestration.md`: head-and-worker pattern, model routing, shared commit and verification rules, the learning rule.
- Privacy gate: the owner-neutral content check also rejects the maintainer's personal, family, client and business identity terms, email addresses and non-loopback IPv4 literals, with tests. Three behaviour-bearing tokens are exempt exactly: the default IANA time zone, one column of a retired manual migration, and one `briefing_type` enum value in the hash-bound schema baselines. Project-specific trust-tier seeds, taxonomy examples and a retired scheduler trigger name were neutralized.

- The MCP server resolves `.env` from `BODHI_ENV_FILE`, then `BODHI_PROJECT_DIR`/`BODHI_ROOT`/`BODHI_PROJECT`, the working directory, `~/bodhi` and `~/Documents/bodhi`; the owner-specific `~/projects/owned/bodhi` defaults are gone. Registering with `BODHI_ENV_FILE` is the documented path.
- `install-harness.mjs --unlink [--root DIR]` removes only generated skill links, for sealed-package upgrades.

Known limits: harness configuration is printed, not merged. The Codex plugin, which cannot pass `BODHI_ENV_FILE`, finds `.env` only when the checkout is `~/bodhi` or `~/Documents/bodhi`. Sealed-package upgrades require `install-harness.mjs --unlink` first (see README). The Claude Code subagent limits in the settings snippet need Claude Code v2.1.217 or later.

- Fresh private team-distribution history, separated from the personal development repository.
- Owner-neutral local substrate, dashboard, MCP adapter and macOS bootstrap/upgrade tooling.
- Workflow discovery, existing-system adoption, operational debugging, component-driven UI and skill behavior evaluation templates.
